# LGM - Turn-based Strategy Game

## Overview
LGM is a turn-based strategy game with a TypeScript backend API and Vue 3 frontend client. This server was generated by the [swagger-codegen](https://github.com/swagger-api/swagger-codegen) project using the [OpenAPI-Spec](https://github.com/OAI/OpenAPI-Specification).

## Quick Start with Nix (REQUIRED)

**Always use the Nix development environment for consistent setup:**

```bash
# Install Nix (if not already installed)
# https://nixos.org/download.html

# Enter the development environment (required first step)
nix-shell

# Install dependencies and start both servers
startup-servers
```

This provides Node.js, npm, git, and helpful development tools. The environment also creates the legacy `lib -> api` symlink and provides convenient aliases; the client itself uses `@lgm/shared-types` and does not need that symlink. See [docs/NIX_SETUP.md](docs/NIX_SETUP.md) for detailed instructions.

## Manual Setup (NOT RECOMMENDED - Use Nix instead)

### Running the API server (manual setup)
To run the server manually, first ensure you have Node.js 24.x and npm installed, then:

```bash
# Install dependencies and start API server
cd api
npm install
npm start  # Production server on port 3000
# OR
npm run monitor  # Development server with auto-restart
```

Without `DATABASE_URL` the API uses an in-memory store and loses state on
restart. Set `DATABASE_URL` to use PostgreSQL; migrations run on first use.

Operational endpoints (no auth required):
- `GET /health` - service health and uptime
- `GET /metrics` - baseline in-memory API request/response metrics

### Running the Frontend (manual setup)
```bash
# Install dependencies and start frontend
cd client  
npm install
npm run dev  # Development server on port 5173
```

### Tests

```bash
# API (Mocha)
cd api && npm test

# Client (Vitest)
cd client && npm run test:unit

# API E2E tests; these need a running API server
cd api && RUN_E2E_TESTS=true npm test
```

### Running Stryker.js Mutation Testing Locally

From `api/`, run `npx stryker run` (it uses `api/stryker.config.json`). Stryker
performs mutation testing and reports on the quality of the test suite.

# Architecture & Development

## 🔐 Authentication Model

LGM uses a **reverse-proxy / forward-auth** pattern. The API is auth-agnostic and trusts identity headers (`Remote-User`, `Remote-Name`, `Remote-Email`, `Remote-Groups`) injected by an upstream nginx + Authelia stack. No bearer tokens are issued or validated by the API itself.

The API also applies baseline hardening in-process: Helmet security headers, IP-based rate limiting, bounded request body parsing, and OpenAPI-backed request validation for incoming JSON payloads.

For local development without a proxy, set `DEV_STUB_USER`:

```bash
DEV_STUB_USER="alice@example.com:Alice Smith:players" npm start
# or pass the header directly:
curl -X POST http://localhost:3000/games -H "Remote-User: alice@example.com"
```

See **[docs/auth.md](docs/auth.md)** for the full deployment topology, nginx config, Authelia rules, environment variables, and threat model.

## Current Status

Implemented: combat and fog of war, per-game player limits with host/kick/start,
player-specific game state, interactive board and order submission, Socket.IO
updates, PostgreSQL persistence with in-memory fallback, proxy authentication,
health/metrics/rate limiting, and unit test suites for both packages.

Known gaps: API response and error consistency, visibility redaction, dead
persistence and legacy code cleanup, and broader E2E/database coverage. Details
and priority order are in
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#known-technical-debt) and
[ROADMAP.md](ROADMAP.md).
